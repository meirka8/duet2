## 1. Process and infrastructure gaps (highest priority)

### 1.1 CI has never been green
Every run on `main` since 2026-08-11 failed with zero jobs executed ("This run likely failed because of a workflow file issue"). Two independent defects, each sufficient on its own:
1. From the first commit (2026-08-11): the MSRV job's `name: MSRV (${{ env.RUST_MSRV }})` uses the `env` context, which GitHub does not permit in a job name.
2. From 2026-08-12 (T-4.1.2): the façade-lint step name `Fail if any crate ... references gpui_component:: directly` is unquoted, and `:: ` inside a plain YAML scalar is a mapping separator, so the file does not even parse (confirmed with PyYAML).

Also found while fixing: the perf gate (T-3.3.5) compares against baselines recorded on the author's workstation; on 2026-09-04 it reported 5 of 14 benchmarks "regressed" on that same machine under CPU contention, so on a GitHub runner it can only ever produce noise. It is now advisory (`continue-on-error`) until baselines are recorded on the runner type itself.

Consequences:
- Definition of Done rule 1 ("merged behind CI green") has been unenforced for the whole project.
- The perf gate (T-3.3.5), the MSRV check, and both isolation lints have never run on a server.
- Once the file parses, more red is expected: the façade lint (`scripts/check-gpui-component-facade.sh`) trips on a doc-comment mention of `gpui_component::input::*` in `crates/duet-ui/src/rename_dialog.rs`, and an Ubuntu runner needs system packages for the gpui/Wayland/Vulkan build.

### 1.2 The UI-thread blocking guard is never armed
`duet-vfs` has 28 `assert_not_ui_thread()` sites (T-3.1.6), but `mark_ui_thread()` has no caller outside the guard's own tests. DoD rule 3 is a no-op today. One call on the GPUI main thread in `duet_ui::run` fixes it.

## 3. Code health and optimizations

- **Monoliths.** `crates/duet-ui/src/workspace.rs` is 9.7k lines with one 2.2k-line `impl`; 20 overlay dialogs share copy-pasted `on_mouse_down_out` scaffolding; `crates/duet-ops/src/executor.rs` is 6k lines. Extract an overlay helper and move `duet-ui`'s 15.9k lines of tests into sibling files (also helps incremental compile time).
- **Test suite cost and flakiness.** `duet-ui`'s 305 tests take 80–335 s under `cargo test` depending on machine load; each spins a real multi-thread Tokio runtime, and 91 `wait_until` polling loops run on 5 s deadlines. Under `cargo-nextest` (one process per test) the whole workspace runs in about 25 s once `duet-ui` tests are capped at cores/4 concurrency, but the run also exposed four tests that assert wall-clock behaviour and fail under contention while passing alone: `operation_manager_end_to_end_pause_resume_via_keyboard`, `two_concurrent_conflicts_are_both_served_not_dropped` (duet-ui), `accelerated_copy_reports_incremental_progress_and_survives_pause_resume` and `plans_100k_files_within_two_seconds_with_accurate_totals` (duet-ops). The nextest config isolates them for now; the real fix is to make them measure work rather than time.
- **Test-harness livelock (found by the first CI run, 2026-09-04).** `two_concurrent_conflicts_are_both_served_not_dropped` hung for the full timeout on the 4-core runner and, pinned to 2 cores, on the workstation. Thread dump: both Tokio workers parked in `ConflictResolver::resolve` waiting for a UI answer; the test thread at 93% CPU inside a window draw under `run_until_parked`. Mechanism: `Workspace::new`'s queue-event consumer loops `while let Some(e) = rx.recv().await { this.update(..) }`, which processes every already-queued event inside one poll; gpui's test-mode `flush_effects` draws the whole window per `update`, and the executor's progress sampler emits every 100 ms, so wherever a debug-build draw takes longer than 100 ms the poll never ends and the test never gets to answer the dialog. Fixed with a one-shot cooperative yield between events (no behaviour change in the real app, where a notify is cheap and the platform draws once per frame) and a bounded tick in the test helper. Lesson for the roadmap: any `while let ... recv().await` consumer that updates the UI needs a yield, and the test helpers must not depend on the executor parking.
- **Executor race: a `Progress` after `Finished` (product bug, found by CI).** `execute` called `sampler.abort()` and immediately sent `Finished`; an aborted sampler already past its interval wait still completes its in-flight send, so a `Progress` could land after `Finished` and resurrect the job's progress entry in the UI forever. Fixed by awaiting the aborted handle before sending `Finished`.
- **Test fixture ordering.** `operation_manager_end_to_end_pause_resume_via_keyboard` enqueued its "slow" copy before opening the manager; on a slow machine the two draws in between outlast the fixture's whole artificial delay, so the job was `Terminal` at the first check (instrumented: 75 ms). Reordered and widened; passes 5/5 pinned to 2 and to 4 cores where it failed 6/6 before.
- **Perf baseline check (2026-09-04).** Re-running the committed benchmarks on the recording machine while idle: all 14 within noise of the 2026-08-12 baselines (`entry_store_population/1M` 38 ms vs 40 ms). The +61% seen in a loaded run was memory-state noise, not a regression; it is also a demonstration of why the gate cannot be trusted on shared runners.
- **Lint and doc posture.** Workspace lints are `clippy::all = "warn"` only; no `#![forbid(unsafe_code)]` on the nine crates that contain no `unsafe`; 11 `clippy::too_many_arguments` allows in `duet-ui` point at missing parameter structs; 82 rustdoc warnings (mostly broken intra-doc links and links to private items).
- **Dependencies and supply chain.** 785 crates in the graph; no `cargo-deny` / `cargo-audit` in CI; no `rust-toolchain.toml`. Duplicates (`ttf-parser` ×3, `wayland-protocols` ×2, `winnow` ×2) all come via gpui. The vendored gpui/blade patch (ADR-007) is a standing obligation; upstreaming it retires it.
- **Release profile** is untouched: no LTO, `codegen-units = 1`, or `strip`. Cheap wins for a project whose pitch is speed.
- **Repo hygiene.** No `README.md` at the root; a stray 460 KB `rust_out` binary (2026-08-07) in the tree; `AGENTS.md` mandates a workflow (Volute MCP logging, phase-gate master PRs, `invoke_subagent`) that nobody follows, so it misleads the next agent.

- Decisions are written down (ADR-001…007, gate reports, spike reports) with honest "what we did not verify" sections.
- Architectural isolation (ADR-002, R-G7) is lint-enforced and holds.
- The trash implementation, the journal/recovery design, and the copy planner are careful, spec-driven code.
